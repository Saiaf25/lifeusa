Development Ticket · LIFE-WIX-MOBILE-001

Restore the Wix Mobile Viewport

LifeUSA currently serves its 980 px desktop canvas to phones. This ticket defines the Wix setting change, mobile-editor repair, and release tests required to restore a responsive mobile layout.

Critical Sitewide Remediation pending Confirmed July 28, 2026
Summary Scope Evidence Cause Implementation Acceptance Rollback

Bottom Line

The live site fits on a phone by shrinking the desktop page, not by responding to the device. A 390 px iPhone receives a 980 px layout viewport and displays the page at approximately 39.8% scale.

Ticket Status

Pending Diagnosis confirmed. Wix Editor change and mobile-layout QA remain.

Root-Cause Assessment

High-Confidence Diagnosis

Wix Editor's Mobile Friendly view is disabled. Wix documents that this state displays the desktop version on mobile devices, which matches the live behavior.

Authenticated Confirmation

Open the production site in Wix Editor, inspect Settings → Mobile Friendly, and capture the current toggle state before changing it.

Rejected shortcut: overflow-x: hidden can conceal clipping, but it cannot create a mobile menu, restore readable sizing, or reflow the 980 px desktop canvas.

Implementation Plan

Phase 1

Enable Wix mobile rendering

  1. Open the production site in Wix Editor.
  2. Open Settings → Mobile Friendly.
  3. Record the current disabled state, then enable Mobile Friendly.
  4. Switch to the mobile editor. Do not publish yet.
Phase 2

Repair the generated mobile layout

  • Replace the desktop navigation bar with the Wix mobile menu.
  • Resize and position the logo, language selector, account, donate, search, and social controls.
  • Reflow hero copy, counters, cards, galleries, forms, image/text sections, and footer columns.
  • Review Hidden on Mobile, spacing, overlaps, gridlines, clipped text, and touch targets.
  • Test Arabic separately for RTL order, alignment, menu behavior, and clipping.
Phase 3

Release after mobile QA

Test the unpublished mobile view at the target widths, publish only when it passes, then repeat the same checks on the public cache-bypassed site.

Definition of Done

  • Mobile HTML uses a device-width viewport, not width=980.
  • 320, 360, 375, 390, 412, and 430 px widths render as mobile layouts.
  • Shared Wix root, header, and page containers are no longer fixed at 980 px.
  • No unintended horizontal scrolling exists.
  • Body text is readable without zooming.
  • The mobile menu opens, closes, scrolls, and reaches every primary destination.
  • Language, account, donate, search, social, and form controls remain tappable.
  • Homepage, About, Programs, Ways to Give, Blog, Donate entry, Privacy, and Arabic pass.
  • Portrait and landscape pass on iOS Safari and Android Chrome.
  • Desktop at 1440 px remains visually unchanged.

Rollback and References

If the generated mobile layout contains a release-blocking defect, do not publish it. If a published change must be reversed, restore the previous Wix site version. Turning Mobile Friendly off again is an emergency rollback only because it restores the confirmed defect.
